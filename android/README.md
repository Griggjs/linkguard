# 护链 Android 应用

在 DNS 层执行白名单：名单外的网站无法解析，因此打不开。选白名单的理由见[根目录 README](../README.md#为什么用白名单)。

版本 **v3.9（24）**，要求 **Android 15 及以上**（`minSdk = 35`）。

## 安装

把 APK 传到手机后：

1. 点击 APK，系统提示「不允许安装此来源」，点设置允许一次
2. 返回继续安装，装完把该权限关回去
3. 若提示「纯净模式」或「风险应用」，点「仍要安装」；仍不行则到
设置 → 应用管理 → 右上角 ⋮ → 关闭纯净模式

应用使用自签名，会提示「未知开发者」，属正常。

## 首次配置

1. 设置管理密码（4–8 位数字），用于切换模式和进入网站管理
2. 点「开启保护」，在系统弹窗中勾选「我信任此应用」后确定
3. 允许通知（Android 13+）。拒绝不影响拦截，只是看不到状态栏提示
4. 确认状态栏出现钥匙图标，主界面显示「防护运行中」

## 保活设置

不做这一步，保护可能会在几小时后被系统清理，且界面不会提示已失效。

|品牌|设置|
|-|-|
|小米 / Redmi|应用管理 → 护链 → 省电策略「无限制」；自启动「允许」；最近任务卡片加锁|
|华为 / 荣耀|应用启动管理 → 关闭「自动管理」，手动三项全允许；电池优化设为「不允许」|
|OPPO / 一加 / realme|电池 → 应用耗电管理 → 允许后台运行与自启动|
|vivo / iQOO|电池 → 后台高耗电 → 允许；自启动管理 → 允许|

过一段时间回来确认钥匙图标还在，就能判断设置是否生效。

## 三种模式

|模式|行为|使用场景|
|-|-|-|
|严格模式（默认）|只放行白名单内的网站|日常|
|智能模式|默认放行，只拦高风险域名特征|严格模式阻挡正常软件使用|
|排查模式|不拦截，只记录|判断问题是否由护链造成|

智能模式的五条规则都在 `SuspiciousRules.kt`：`xn--` 同形字、38 个廉价后缀、含品牌词但不在官方域下、两个以上诱导性词拼接、连字符超过四个。

切换模式需要密码。切换只更换判定引擎，不重建 VPN、不清系统缓存，所以已经解析过的域名会继续命中缓存直到过期。

## 软件打不开

**学习（推荐）**：高级设置 → 网站管理 →「打不开某个软件？让它学习一下」，然后打开那个软件用一分钟，回到护链确认即可。

记录期间会自动折叠子域名、剔除广告与追踪域名、跳过已在白名单的条目。少于 15 秒不结束，超过 30 分钟自动作废。

**手动添加**：网站管理页的搜索框下方有输入框，支持粘贴完整链接。加入一个域名后其所有子域名一并放行。

**从记录里挑**：展开「待处理记录」，搜索后点「加入白名单」。

## 网站管理页

```
白名单 147 条（内置 146 · 手动 1） · 待处理记录 376 条

▸ 待处理记录（376 条）（点击展开）
▾ 白名单（147 条）（点击收起）
    搜索白名单 / 添加输入框
    ▸ 内置（146 条）（点击展开）
    〔 重置白名单（清除手动添加的 N 条）〕
```

两个搜索框互相独立。内置条目随应用发布，包含各厂商系统联网、推送、应用商店域名以及运营商语音与时间同步域名，不可删除。重置只清除手动添加的条目。

## 通知栏

保护运行时状态栏有一条常驻通知，显示当前模式与累计拦截次数，点击回到主界面。

以[前台服务](https://developer.android.com/develop/background-work/services/fgs)运行，降低被系统回收的概率。Android 11 起系统允许用户清除前台服务通知，因此每 15 秒检查一次，被清除后重新挂上。通知消失不代表拦截停止，以主界面状态为准。

## 一键诊断

主界面 →「检查网络与拦截状态」。它不走系统缓存，而是手工构造 DNS 报文直连护链的虚拟 DNS，测的是真实链路。

```
防护状态：运行中
规则自检：8/8 项通过
常用网站连通性：百度 正常 / 淘宝图片 正常 / 京东图片 正常 / 微信 正常 / 陌生网站 已拦截
上游 DNS：192.168.31.1 可达 / 223.5.5.5 可达
内部统计：收 1184 · 答 1165 · 非DNS 19（TCP 0）· 解析失败 0 · 上游失败 0 · 写回失败 0 · TCP回退 0 · 重启 0
```

内部统计的读法：

|现象|含义|
|-|-|
|收 0|查询没有进入护链，VPN 未生效|
|收 >0 而答 0|报文解析全部失败|
|上游失败持续增长|转发故障，或网络到不了上游 DNS|
|写回失败增长|应答包过大或写入隧道失败|
|重启增长|读线程异常退出后被看门狗重建|

## 故障排查

|症状|处理|
|-|-|
|显示"已连接但无法访问互联网"|确认 `connectivitycheck.gstatic.com` 与对应厂商域名在白名单内|
|时间不准、HTTPS 报证书错误|确认 `ntp.org`、`time.android.com` 在白名单内|
|电话异常|确认 `10086.cn` 等运营商域名在白名单内|
|没有护链通知|应用管理 → 护链 → 通知管理 → 允许|
|过一段时间保护自己停了|重做保活设置|
|严格模式下大量网站打不开|属于该模式的预期行为，用学习或手动添加解决|
|智能模式下仍有高风险链接能进|域名层判断的固有限制，改用严格模式|

## 能力边界

智能模式，以及所有 DNS 级方案，都拦不住这些：域名正常但内容是骗局、正规站被入侵后挂的马、云存储桶中的钓鱼页、同一域名下的钓鱼路径、已缓存的 IP 与已建立的长连接、应用自带 DoH 或 HTTPDNS 的解析、已安装的木马与已授予的无障碍权限。

当前不支持 Android 14 及以下（`minSdk = 35`），也不支持 iOS。

要更严格只有严格模式（默认拒绝）；要看清页面内容需要无障碍服务读取屏幕，本项目未实现。

## 代码结构

纯逻辑层不依赖 Android，可在 JVM 上单测：

```
DomainSet.kt        域名后缀匹配（域及其子域语义）
DnsMessage.kt       DNS 报文解析构造、应答裁剪、EDNS 上限钳制
Ipv4.kt             IPv4 与 UDP 报文拆装、校验和
DnsProxy.kt         应答包的地址与端口对调
GuardEngine.kt      判定引擎（三种模式）
SuspiciousRules.kt  智能模式的域名特征
LearnedFilter.kt    学习结果清洗
Stats.kt            内部计数
```

Android 层无法脱离真机验证：

```
GuardVpnService.kt  VpnService、TUN 读写、并发转发、前台通知、看门狗
MainActivity.kt     主界面、模式下拉框、学习流程、诊断
ApprovalsActivity.kt 白名单与被拦记录
PinActivity.kt      密码
Prefs.kt            密码哈希、白名单、学习状态、开关
BlockLog.kt         被拦记录
LearnedLog.kt       学习期间记录被放行的域名
Ui.kt               界面构建
```

几个实现上的取舍：

* 只接管 DNS，`addRoute` 只加一条 `/32`。无法按 IP 拦截，但耗电与速度基本无感，也不会因为转发出错导致整机断网。
* 拦截时合成 NXDOMAIN，不返回 0.0.0.0，让客户端立刻失败而不是等待超时。
* 16 路线程池并发处理，每个查询开独立 socket。共享 socket 会让并发线程收到彼此的应答，DNS 结果错乱。
* 上游应答被截断（TC 位）时改用 TCP 重查；结果超过隧道 MTU 时按记录边界裁剪并清除 TC 位。
* 不改上游 TTL，让已放行的网站按正常节奏留在系统缓存里。
* 切换模式不重建 VPN，避免清空缓存导致刚放行的软件立刻被拦。

## 构建

```powershell
.\build.ps1
```

先跑单元测试再打包，产物在 `app/build/outputs/apk/debug/app-debug.apk`。

需要 JDK 17+、Android SDK（platform-35、build-tools 35.0.0）、Gradle 8.9。环境脚本：[../tools/setup-android-sdk.ps1](../tools/setup-android-sdk.ps1)。

改内置白名单编辑 `BuiltinRules.kt`；日常加域名用应用内界面即可，不需要改代码。

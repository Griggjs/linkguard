# 能力边界

这份文档是避免误判——护链的功能是"降低概率"，而非"提供保证"。

## 护链能做到的

* **拦截明确恶意的域名**：公开情报库里收录的钓鱼、木马、诈骗域名，以及按规则判定为高风险的域名
* **白名单模式下的默认拒绝**：不在名单里的网站无法完成解析，也就无法被打开
* **拦截发生在建立连接之前**：被拦的域名不会向上游发出查询，对方服务器看不到任何请求
* **对全家生效**：手机应用对整机生效；PC 端在形态 B 下对家里所有设备生效
* **不需要老人做任何操作**：安装与配置由子女完成，之后是自动运行
* **离线运行**：不联网、不上传、无账号、无遥测，判定全在本地完成

## 做不到的

### 一、看不清页面内容

DNS 只能看到域名。域名正常、页面内容是仿冒的情况下，无论规则做得多细都判断不出来。要看清页面需要读取屏幕，那是无障碍服务的权限等级，本项目未实现。

### 二、拦不住域名在白名单里的钓鱼页

正规网站被入侵后挂的马、共享 CDN 上的钓鱼页、云存储桶里的页面，域名都在白名单里（放行它们是为了让图片和视频能正常加载）。这类只能靠浏览器层面的告警，以及"不点陌生链接"的习惯。

### 三、看不到 HTTPS 的路径

同一个域名下的 `/login` 和 `/pay` 对 DNS 完全不可见。路径级拦截需要中间人证书，这在家庭场景里不可接受。

### 四、管不了已经发生的连接

拦截只发生在"域名解析为 IP"这一步。已经缓存的 IP、已经建立的长连接、应用内部硬编码的 IP，都拦不到。

### 五、管不了自带加密 DNS 的应用

部分应用内置 DoH 或 HTTPDNS，域名解析在自己的服务器上完成，不经过系统 DNS。任何 DNS 级方案对它都无效。

### 六、管不了已经装上的木马与已授予的权限

被授予无障碍、设备管理、读取短信权限的应用，在系统层面已经拥有了足够的能力。这不是 DNS 能处理的层次，只能靠事先的安装限制和定期的权限检查。

### 七、挡不住本人主动填写

绝大多数实际损失发生在受害者自己输入卡号、密码、验证码的那一刻。工具能让"打开诈骗页面"这一步失败，但如果页面已经打开，后续操作无人可挡。

### 八、平台限制

* Android 14 及以下装不上当前版本（`minSdk = 35`）
* iOS 不允许第三方应用做全局 DNS 过滤，只能改 WiFi 的 DNS，且仅在特定 WiFi 下有效
* 所有国产 ROM 的省电策略都可能清理后台服务，必须做保活设置

## 无需冗余功能

技术上，结合无障碍服务读取页面内容可以做到更准确的识别，但代价是：

* 需要最高等级的权限，等于把整台手机的控制权交给这个应用
* 误判会直接阻断正常操作，老人无法自行恢复
* 这类权限一旦被滥用，后果比它要防的问题更严重
* 这只是一个轻量化的小软件

本地规则加白名单的方案，能力有限但可预测：出错时表现为"打不开"，用户可以立刻发现并修正。对家庭场景来说，可预测比覆盖率高更重要。

## 可能的开发方向

按对实际效果的贡献排序：

1. **降低系统要求到 Android 10 及以上**，让更多存量机型可以用上
2. **补全各品牌系统域名**，减少严格模式下的误拦与"已连接但无法上网"
3. **扩大高发诈骗后缀与品牌词规则**，提高智能模式的召回
4. **接入可人工维护的本地黑名单**，补充白名单覆盖不到的场景
5. 无障碍服务读取屏幕并识别仿冒页面，视权限代价决定是否实现

前四项都不改变现有权限模型，第五项需要重新评估。

## 最后

这个工具降低概率，不提供保证。

遇到真的被骗，请立刻拨通银行客服电话冻结银行卡，拨打 96110，保留设备固定证据。越早挂失，追回的可能性和可挽回的损失越大。

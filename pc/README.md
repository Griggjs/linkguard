# PC 端工具（已被手机应用取代）

这是护链最早形态：在家里电脑上跑的链接判定工具，加一个本地 DNS 过滤服务。它要求使用者**主动把可疑链接拿去查**，把防线建在了老人最容易出错的一步上。现在的方案是 [手机应用](../android/README.md)。

保留它的原因有两个：判定规则是理解整套防护的基础；而且它能在不改手机的前提下先跑起来看效果。

## 三部分

| 组件 | 作用 |
|---|---|
| `analyzer.py` | 给一条链接打分：冒充品牌、形近域名、安装包直链、伪协议、`@` 混淆、IP 直连、同形字、可疑后缀、短链、嵌套跳转、诈骗话术 |
| `sinkhole.py` | 本地 DNS 过滤服务，把恶意域名解析成 `0.0.0.0`，对局域网内所有设备生效 |
| `server.py` | 手机浏览器可打开的大字版查链接页面，服务端渲染，不依赖 JS |

辅助模块：`feeds.py` 抓取并解析公开恶意域名名单（hosts、AdGuard、CSV、JSON 四种格式），`store.py` 用 SQLite 存名单与查询日志，`resolver.py` 展开短链与重定向链（唯一联网环节，带 SSRF 防护），`cli.py` 是命令行入口。

## 快速开始

```powershell
# 在本目录执行
.\scripts\run.ps1 serve --port 8088
```

命令行会打印本机与局域网访问地址。手机连同一个 WiFi 后打开局域网地址，把可疑链接粘进去即可。

DNS 过滤：

```powershell
.\scripts\run.ps1 dns --port 53
```

然后把手机或路由器的 DNS 指向这台电脑的局域网 IP。路由器的 DNS 设置里把主 DNS 改为电脑的局域网 IP，改完重启 DHCP、手机断开重连 WiFi 才会生效。

单条链接检查：

```powershell
.\scripts\run.ps1 check "http://icbc-login.top/verify?card=1"
```

## 常用命令

| 命令 | 作用 |
|---|---|
| `selftest` | 自检，部署后先跑一次 |
| `check <链接>` | 检查一条链接，`--resolve` 会联网展开短链 |
| `serve` | 启动网页版 |
| `dns` | 启动 DNS 过滤 |
| `feeds --update` | 更新恶意域名名单（需联网，会生成 `data/linkguard.db`） |
| `feeds --add-domain` | 手动加入一个域名 |
| `export --format hosts` | 导出为 hosts、dnsmasq 或 AdGuard 规则 |
| `audit` | 名单体检，确认没有误拦正规站点，`--fix` 一键移除 |

数据库是生成物，已从仓库移除。首次使用需跑一次 `feeds --update`。

## 验证状态

99 个单元测试全部通过，覆盖判定引擎、DNS 报文与转发、名单解析、重定向追踪、HTTP 接口。

DNS 过滤做过真实报文验证：命中名单的域名返回 `0.0.0.0`，正常域名转发到真实上游并拿到应答，缓存命中不再问上游。

名单更新实测过一次，五个源共入库约 59 万条域名。同一个过程中发现两个问题：hosts 文件的行内注释被误当成域名，导致 `github.com` 被整体拦截；URLhaus 的官方下载端点已全部返回 410，源已失效。前者已修复并加了回归测试，`audit` 命令就是为这类误拦准备的。

## 注意事项

- 服务没有登录认证，只适合在家庭局域网内使用，不要做端口映射
- 查询日志会记录访问过的域名，使用者应当知情
- 名单对中文诈骗站的覆盖有限，内置源都是国外公开情报
